# Validation and Wet-Run

Obiettivo:
validare il cambiamento con test reali e con evidenza di esecuzione.

Regole:
- definisci prima il test che deve fallire
- poi il minimo cambiamento per farlo passare
- poi esegui i test reali
- poi raccogli evidenza
- se il wet-run non è possibile, spiega il motivo e distingui il limite dell’ambiente dal bug del codice

Output richiesto:
- test plan
- commands
- results
- regressions
- evidence
- residual risks
